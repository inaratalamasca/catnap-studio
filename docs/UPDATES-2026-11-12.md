# Catnap audio and Theatre update — November 12, 2026

## Listening now

Open [the player](https://listen.catnapradio.com/) during a Catnap broadcast.
Choose **Live** for low delay or **Radio** for buffered mobile listening. Mute
the Discord presentation's stream audio and leave individual voices audible.

Live carries stereo Opus at a 256 kbps target. Radio receives one copy on the
server and makes 320 kbps stereo MP3 at 48 kHz. Both share one host upload.
The host verified Live on desktop and Android cellular, reporting below-one-
second delay on cellular. Yard Wi-Fi was inconsistent over UDP; the explicit
[TCP connection](https://listen.catnapradio.com/?route=tcp) played steadily on
the tested phone and tablet. This remains a useful local workaround.

Receive-only WebRTC stopped when the tested mobile browsers lost the foreground.
The conventional Radio stream kept playing through phone app switching and an
approximately two-minute screen-lock test. This is an actual phone result;
iPhone and long-duration phone-call/Bluetooth behavior still need their own checks.

The web page and signaling may use Cloudflare. Radio audio uses a separate
direct HTTPS origin; WebRTC media also goes directly to the local relay. No VPS
was required for this pilot. Dedicated application storage has before/after and
hourly ZFS snapshots. Private keys and network installation records stay outside
the repositories.

## New player display

The new development publisher supplies public song information from its exact
captured Suno tab. The listener shows the last observed track above the current
song, current artwork/title/artist, and three upcoming tracks. A scrollable
expanded view can show up to 100 loaded upcoming rows. It does not scroll Suno,
change the host's playlist or claim to know the internal shuffled queue.

Wait estimates appear only in the expanded view and only when current remaining
time and preceding track durations are known. Unknown timing stays unavailable;
there is no invented average track length. These estimates follow the host's
timeline. Radio audio has its own buffer and can trail that timeline.

If the page does not expose upcoming durations, the hosting assistant can import
a verified duration catalog through Suno MCP reads. The server joins exact song
IDs and fills only missing durations. That private catalog is bounded and
persisted separately from source; live order, elapsed time and paused state still
come from the broadcasting tab. Paused playback suspends countdown estimates.

Metadata expires after 30 seconds without fresh publication. Stop or a stale
session clears the recent-track history. Repeated heartbeats do not create
duplicate last-played entries. Song information is optional: a metadata failure
does not stop audio. No progress bar was added.

This display requires the new publisher build; the currently running older
extension is not silently reloaded to turn it on. The host manually activated the
standalone 0.4.0 build during this run; its real song artwork and 21 loaded
upcoming tracks were verified in the listener. A cache-versioned stylesheet fix
keeps the cover bounded, and expansion replaces the short three-song view.

## Standalone and integrated Theatre

The 0.5.0 development build moves presentation options fully into the persistent
control window. The Theatre canvas keeps one **Controls** entry alongside its
normal playback/navigation and Close controls. Layout, lyrics, branding, local
visuals and banners are adjusted off the presentation surface.

An optional music-reactive background visualizer adds translucent teal/lavender
bars along the lower edge, beneath artwork, lyrics, playlist and other controls.
It uses cloned stream-backed music or the existing HQ broadcaster analyser, with
on/off and transparency controls in the pop-out. URL-only playback without HQ
broadcasting stays quiet. Rendering is bounded and silence settles to a quiet
background. It does not request microphone audio or add another broadcast.

Both development builds now include the same presentation controls: layouts,
lyric size and following, branding and local images, local GIF/video overlays,
quick banners and settings import/export. **Controls ↗** opens
a persistent window bound to its originating Suno tab. Closing that window
leaves Theatre running. The panel reuses the existing handlers and shared settings; legacy DOM adapters stay hidden for controller compatibility.

The integrated build preserves the existing advanced visual-command bridge and
its protocol version. Shared files have a guarded sync script and hash inventory
so later presentation updates can be checked across both builds. This is
presentation parity, not a claim that every advanced hosting roadmap feature is
finished. External-video/placeholder metadata remains subject to the actual
advanced source integration.

Normal AIU submission guidance points to the uploader. A clearly labeled
emergency/non-AIU chat-drop banner remains available for the retained exception.

The new builds are prepared separately from installed source. Load them between
broadcasts: changing extensions during a live capture can interrupt the music.
Real isolated Chromium checks cover panel reuse, source binding, shared settings,
banner/file operations and absence of unintended playback/capture actions.
The 0.5 checks also cover a stale panel-state race, actual generated stream audio
reacting/fading, and preserved native audio through disable/re-enable/source
changes. The running 0.4 extension was left untouched.
